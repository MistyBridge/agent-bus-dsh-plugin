> 本文档是 `dsh-agent-bus` v1.1「任务进度可视化面板」的完整实现规格,供外部前端工程师独立实现使用。
> 实现所需的全部接口、数据形状、约束与验收标准均在本文件内。

## 1. 背景与目标

dsh-agent-bus 是一个 DeepSeek Harness 插件,在工作区内的多个 agent 会话之间提供任务派发/执行/验收网关。所有任务记录持久化在磁盘台账(domain storage)中,包含 A2A 对齐的 8 态生命周期、重做计数、验收结论、报告内容(内联或外置到热/冷报告存储)。

**目标**:在 dsh Web 界面提供一个常驻的任务监控面板,让用户以工作区为维度俯瞰全部任务:谁在派发、谁在执行、谁在验收、卡在哪一步、重做几次、每人消耗了多少 token、报告是内联还是已归档。

**交互形态**(用户定义):

```
收缩态                聚焦(hover)             展开(click)
┌───┐                ┌──────────────┐        ┌──────────────────────────────┐
│ 3 │ ← 胶囊,吸附右侧  │ 活动预览浮层   │        │ ┌─ 顶栏:工作区选择条(可点击)─┐ │
└───┘                └──────────────┘        │ ├──┬─────────────────────────┤ │
  ↑                                            │ 会 │ 未结算任务卡片列表        │ │
  右侧边缘,垂直方向                             │ 话 │   (状态点 + 收起的主干)    │ │
                                               │ 侧 │ 工作人员目录 + token 用量  │ │
                                               │ 边 │                         │ │
                                               │ 栏 │                         │ │
                                               └───┴─────────────────────────┘ │
                                               └──────────────────────────────┘
```

**范围边界(本期明确不做)**:

| 不做 | 原因 |
|---|---|
| 面板内操作(取消/验收/重派) | 客户端无法调用 agent 工具;v1.1 纯只读 |
| 通知历史 | 通知是 inbox 消息,无持久化数据源,需 ledger 加字段(属 v1.2) |
| DAG 任务流可视化 | 远期规划,见第 8 章;本期仅保证数据契约可平滑演进 |
| 会话内卡片(`conversation.chat.node`) | 属 v1.2 |

```

│   └─ webServer.register()    ── GET /plugins/dsh-agent-bus/state       │

        ▲ 轮询 fetch (每 2s, cache: no-store)
```

**通道选型理由**(已调研,dsh 源码不可改):

| 候选通道 | 结论 |
|---|---|
| `host/remote-event`(api-remotes 白名单) | ❌ 白名单 `API_REMOTE_FORWARDED_EVENTS` 是 dsh 源码内封闭数组 |
| `session/projection`(`ctx.sessionProjections`) | ❌ 投递面 per-session 且帧联合封闭;但 **token 数据源正来自它**(见 3.5) |
| 自定义 RPC 方法(`events.mux/host` 帧) | ❌ 帧联合类型在 dsh 源码内封闭 |
| **插件自建 HTTP 路由 + 客户端轮询** | ✅ `ctx.webServer.register()` 是公开服务;dsh-agent-teams 已用此模式生产验证 |

## 3. 宿主端(Host)实现规格

### 3.1 路由注册(懒注册模式)

`webServer` 服务只在 Web profile 存在;headless profile 没有它。**不得**把 `webServer` 加入 `inject`(会导致 headless 启动失败)。采用懒注册模式(同 dsh-agent-teams):

```ts
// src/index.ts apply() 内,与 tools/ledger 注册并列:

let webRegistered = false
const registerWebSurface = (): void => {
  if (webRegistered) return
  const webServer = ctx.get('webServer') as WebRouteHost | undefined
  if (webServer === undefined) return
  webRegistered = true
  ctx.effect(() => webServer.register({
    kind: 'exact',
    path: '/plugins/dsh-agent-bus/state',
    handler: async (_req, res) => {
      try {
        const snapshot = await buildPanelSnapshot(ctx, ledger, reports)
        res.writeHead(200, {
          'content-type': 'application/json; charset=utf-8',
          'cache-control': 'no-store',
        })
        res.end(JSON.stringify(snapshot))
      } catch (error: unknown) {
        ctx.logger.warn(`agent-bus: state route failed: ${String(error)}`)
        res.writeHead(500, { 'content-type': 'application/json; charset=utf-8' })
        res.end(JSON.stringify({ error: 'snapshot-failed' }))
      }
    },
  }), 'agent-bus: panel route')
}

registerWebSurface()
ctx.on('internal/service', (name) => {
  if (name === 'webServer') registerWebSurface()
})
```

`WebRouteHost` 结构类型(与 dsh 源码 `packages/host/webserver` 的 `WebRoute` 一致):

```ts
interface WebRouteHost {
  register(route: {
    kind: 'exact' | 'prefix'
    path: string
    handler: (req: IncomingMessage, res: ServerResponse) => void | Promise<void>
  }): () => void
}
```

### 3.2 数据源(全部经 `ctx.get` 可选获取,任何一项缺失都不阻塞快照)

| 数据 | 获取方式 | 缺失时 |
|---|---|---|
| 工作区名录 | `ctx.get('workspaceRegistry')?.list()` → `{id, title, path}`[] | `workspaces: []` |
| 工作区的会话归属 | 每工作区 `.sessionIds`(Registry 实体自带,header 校验过) | 空数组 |
| live 会话 | `ctx.get('sessions')`;`sessions.get(id)` 判断在不在线 | 视为离线 |
| 会话标题 | 磁盘 `~/.dsh/storages/session_projcache.json`(见 3.3) | id 前 8 位 |
| token 用量(仅任务期间差值用) | `ctx.get('sessionProjections')?.snapshot(session).values['tokenUsage']`(见 3.5) | 差值字段 `null` |
| 台账 | 进程内 `ledger.listAll()` | — |
| 报告冷热区 | 文件系统探测(见 3.4) | — |

**会话归属注意**:`sessionIds` 是"候选账户"(仅 header 校验过的会话,离线/已 dispose 的不在内)。侧边栏会话列表 = `workspace.sessionIds` 全部(含离线的,标记"离线")∪ 任务中引用但不在列表内的会话(标记"离线")。live 的排前面。

### 3.3 会话标题解析(src/titles.ts,新增)

权威来源是磁盘 `~/.dsh/storages/session_projcache.json`(与 e2e 测试同源;**绝不解析页面文本**):

```ts
// 输入: session_projcache.json 的 JSON 对象
// 输出: Map<SessionId, title>
// 结构: d.tables.sessions[sid].rows.title.val (string) —— 只取 val 为非空字符串的条目
// 失败(文件缺失/解析错误): 返回空 Map,调用方 fallback 到 SessionId 前 8 字符
```

要点:
- 每次构建快照时读取(文件小,2s 轮询下开销可忽略);不做缓存,避免与 e2e 磁盘解析产生分歧。
- 函数接受解析后的 JSON 入参(可单测),文件读取单独包一层。

### 3.4 报告存储区(zone)探测

ledger 行上的 `reportRef` 存在时,报告外置在磁盘。**冷热分区由文件位置决定**,ledger 记录不含 zone 字段,路由侧探测:

```ts
// src/panel.ts
async function detectReportZone(
  reports: ReportStore, task: TaskRecord,
): Promise<'inline' | 'hot' | 'cold' | 'missing' | null> {
  if (task.report !== undefined && task.reportRef === undefined) return 'inline'
  if (task.reportRef === undefined) return null // 无报告
  // hot → cold 依次探测文件存在性;两者都不在 → missing(已清扫或从未落盘)
}
```

实现要求:在 `ReportStore` 上新增 `existsHot(ref)` / `existsCold(ref)`(`stat` 失败即不存在,空目录异常按不存在处理)。**不改动 ledger schema、不 bump domain 版本。**

### 3.5 token 用量数据源(host 端零磁盘 IO)

token-meter 插件在 session-projection 注册了 `tokenUsage` 投影单元,折叠会话日志中的 `assistant/chunk`(chunk.type==='usage')与 `assistant/message`(data.usage)事件,同 turn/step 替换不重复计数。host 端直接取:

```ts
const projections = ctx.get('sessionProjections')
// 对每个 live session:
const tokens = projections?.snapshot(session).values['tokenUsage']
// → { uncachedInputTokens, outputTokens, cacheReadTokens, cacheWriteTokens } | undefined
```

- 只对 **live session** 可读;离线会话读不到。
- 快照是进程内同步读,轮询下无 IO 压力。

**职责边界**:会话级全局用量(token 总消耗)由 **dsh 原生 UI 显示**(tokenUsage 投影经 session/projection 帧推送到 ui-conversation),**插件不统计、面板不重复展示**。插件只负责任务维度的两层:

| 口径 | 数据 | 用在哪 |
|---|---|---|
| 任务期间消耗(按会话) | 当前投影 − 派发时快照 | 任务卡片工作人员目录每行(`staff[].tokensInTask`) |
| 任务合计(求和) | staff 各 tokensInTask 求和 | 任务卡片工作人员目录标题行(`taskTokensTotal`;**求和不替代明细**,每会话原始差值必须保留显示) |

**任务期间消耗 = 派发时快照 + 结算前差值**。机制:

1. **派发时快照(ledger 持久化)**:`dispatch_task` 成功投递后,宿主端对三个参与者(去重,角色缺省按 3.7 规则)各记录一次当时的会话累计用量,存入任务行新字段 `tokensAtStart`:

```ts
// types.ts 新增
interface TokenBuckets {
  uncachedInputTokens: number; outputTokens: number
  cacheReadTokens: number; cacheWriteTokens: number
}
// TaskRecord 新增(domain v5):
readonly tokensAtStart?: Record<SessionId, TokenBuckets>
```

   参与者会话当时离线或投影不可用 → 该会话不写入(字段缺省,面板显示 null,不重试——任务生命周期内只快照这一次)。

2. **展示时差值(路由计算)**:`staff[].tokensInTask = max(0, 当前投影 − tokensAtStart[sessionId])`;当前投影不可读(会话离线)或起始快照缺失 → `null`。差值在路由侧 clamp 到 ≥0(投影是 last-wins 折叠,理论上不回退,clamp 只是防御)。

3. **已结算任务不再显示**在面板主列表(4.3),故不存在"结算后差值继续增长"的展示问题;若未来展示已结算任务,届时再考虑结算时刻锁存(属 v1.2)。

**正确性前提**:单个 agent 会话不并发——同一会话同一时刻只有一个 turn 在执行,任务期间该会话的 token 消耗 = 结束累计 − 开始累计,差值精确无叠加误差。会话全程只被这一任务占用时该口径即任务真实消耗;若会话在任务期间还处理了其他事务,差值包含其全部消耗(台账无按任务归集能力,此偏差可接受并在 UI 标注"任务期间消耗")。

**schema 演进代价**:`agent_bus` domain version 4 → 5,升级时删除 `~/.dsh/storages/agent_bus.json` 重新生成(与 v3→v4 相同流程,无迁移)。`tokensAtStart` 为 optional,旧行解析兼容。

### 3.7 TaskView(每条任务的行形状)

从 `TaskRecord` 投影,**不输出 report 全文**(报告可能很大;只输出摘要与存储位置):

```ts
interface TaskView {
  id: string                    // TaskId 全量
  workspacePath: string         // 任务归属工作区路径(客户端按选中工作区过滤)
  status: TaskStatus            // 8 态之一(见 src/types.ts)
  settled: boolean              // 已结算:completed+outcome!==null / failed / canceled
  content: string               // 任务指令,原样
  contentPreview: string        // content 截断到 120 码点,超长加 …
  mode: 'followup' | 'steer'
  assignedBy: string            // SessionId
  assignedTo: string | null     // undefined → null
  assignedReviewer: string | null
  byTitle: string               // 解析后的会话名(3.3 fallback 规则)
  toTitle: string | null
  reviewerTitle: string | null
  retries: number
  reason: string | null         // failed 行的分类(timeout/no-response/discarded/...)
  outcome: 'success' | 'failure' | null
  feedback: string | null       // 最近一次验收反馈(截断 200 码点)
  question: string | null       // input-required 时的提问(截断 200 码点)
  reportZone: 'inline' | 'hot' | 'cold' | 'missing' | null  // 3.4 探测;null = 无报告
  hasReportRef: boolean
  turn: number | null
  staff: StaffEntry[]           // 工作人员目录,见下
  /** 本任务合计 = staff 中 tokensInTask 非 null 项的求和;全 null → null */
  taskTokensTotal: {
    uncachedInputTokens: number; outputTokens: number
    cacheReadTokens: number; cacheWriteTokens: number
  } | null
  createdAt: string             // ISO-8601
  updatedAt: string
  ageMs: number                 // Date.now() - createdAt(路由侧生成,快照时刻一致)
  updatedMs: number             // Date.now() - updatedAt
}

interface StaffEntry {
  sessionId: string
  title: string                 // 3.3 解析;fallback id 前 8 位
  role: 'initiator' | 'executor' | 'reviewer'
  live: boolean                 // 当前在线
  /** 任务期间消耗 = max(0, 当前累计 − tokensAtStart[id]);投影不可读或起始快照缺失 → null */
  tokensInTask: {
    uncachedInputTokens: number; outputTokens: number
    cacheReadTokens: number; cacheWriteTokens: number
  } | null
}
```

`staff` 生成规则:
- 角色:initiator = `assignedBy`;executor = `assignedTo`(缺省跳过);reviewer = `assignedReviewer ?? assignedBy`。
- 去重(initiator===reviewer 时只出现一次,role 取先出现的)。
- 顺序固定:`executor` → `reviewer` → `initiator`(执行在前,发起最后)。
- `tokensInTask` 按 3.5 差值规则计算(clamp ≥0);不参与会话侧边栏的会话(不在 sessionIds 的离线引用)也出现在 staff,`live: false`、`tokensInTask: null`。

**两层 token 口径(任务维度;会话级全局用量由 dsh 原生 UI 显示,插件不重复)**:

| 层 | 数据 | 位置 |
|---|---|---|
| 任务期间消耗(按会话) | `staff[].tokensInTask`(差值) | 任务卡片工作人员目录每行 |
| 任务合计(求和) | `taskTokensTotal`(= staff 各 tokensInTask 求和,全 null → null) | 任务卡片工作人员目录标题行 |

`taskTokensTotal` 在路由侧计算(与 `ageMs` 同源,快照时刻一致);求和只累加 `tokensInTask` 非 null 项,存在任何 null 项时合计仍为部分和(UI 文案"本任务合计 N tokens(部分会话不可读)")。**合计永不替代明细**。

`ageMs` / `updatedMs` 在**路由侧**生成(接受 `now` 参数注入,便于测试)。

### 4.3 三态交互(核心交互规格)

**态 A — 收缩胶囊**(默认):
- 固定定位右侧边缘,垂直居中;窄条胶囊(宽 ~44px,高自适应),圆角朝向左侧。
- 内容:非终态任务数(大数字)+ 工作区小标题(badge 下方小字,如 "1 ws")。无任何任务时显示灰点,点击仍可展开(空态)。
- 吸附动画:展开/收起时胶囊从右侧滑入滑出,≤150ms。
- **光标悬停胶囊 180ms 后弹出预览浮层**(态 B);移出胶囊与浮层 2s 后收回。键盘焦点进入胶囊同样弹浮层(可访问性)。
- 单击胶囊 → 展开完整面板(态 C);再点外部或 Esc 或面板 × 关闭回态 A。

**态 B — 预览浮层**(hover 弹出):
- 小浮层(宽 ~260px)贴在胶囊左侧,列出:
  - 顶行:当前选中工作区名 + 状态统计摘要(如 "进行中 2 · 待验收 1");
  - 下方:最近 3 条活动(按 updatedAt 降序取非终态任务,每行:状态点 + toTitle + contentPreview 截断 60 码点);
  - 无活动:"暂无进行中的任务"。
- 纯展示,无交互(点击穿透到胶囊);2s 无交互自动收回。

**态 C — 展开面板**(右侧抽屉):
- 固定右侧,宽 **380px**,高 100vh(或 80vh 底部留白,二选一,推荐全高贴边);`data-agent-bus-panel-open` 设置在 `<html>` 上,CSS 让主对话列让位 380px;窄视口(<900px)覆盖模式不让位。
- 内部三区布局(自上而下):


**顶栏 — 工作区选择条**:
- 显示当前选中工作区标题;点击弹出下拉列表,列出快照 `workspaces` 全部条目(标题 + path 小字),点击切换。
- 选择状态持久化到 `localStorage['dsh-agent-bus.workspace']`(键名固定);无持久化值时默认第一个工作区。
- 选中工作区变化 → 主界面与侧边栏重筛(本地,不发请求;快照是全量的)。

**会话侧边栏**:
- 数据:快照 `sessions` 中 `workspaceId === 选中工作区` 的条目(live 排前,离线在后标"离线")。
- 首项固定"全部会话"(默认选中)。点击会话 → 主界面只显示该会话**参与**(assignedBy / assignedTo / assignedReviewer 任一匹配)的未结算任务;再次点击取消。
- 每项:状态点(live 绿/灰)+ 标题。会话级全局 token 用量不在此显示(由 dsh 原生 UI 提供)。

**主界面 — 未结算任务卡片**:
- **未结算定义**:`!settled`(即 submitted / working / input-required / completed 且 outcome===null)。已结算任务本期不进入主列表(第 8 章 DAG 落地时再引入已结算视图)。
- 卡片默认收起:一行内显示【状态点 + 状态徽标】+ contentPreview + `byTitle → toTitle` + 相对时间。
- 点击卡片展开:
  - **任务主干(指令全文)**——默认收起,展开后显示完整 content(等宽字体,可滚动,最大高度 240px);
  - 完整字段组:`状态 / 模式 / 重做次数(retries>0)`;`发起 / 执行 / 验收` 三行(带标题);
  - `提问`(input-required 时)、`反馈`(feedback 时)、`失败原因`(failed 时);
  - 报告位置徽标(见 4.5);
  - **工作人员目录**:区块标题行 = "工作人员目录 · 本任务合计 N tokens"(`taskTokensTotal` 四桶求和,千分位;null 显示"合计不可用";有部分 null 项时后缀"部分会话不可读")。staff 列表每行 = 角色标签 + 标题 + live 点 + **任务期间 token 消耗**(四桶合计,千分位,文案"本任务 N tokens";`tokensInTask` 为 null 显示"—")。标题悬停提示明细(uncached/cache-read/cache-write/output 四桶)。**合计必须与每会话明细并存展示——求和永不替代原始明细**。会话级全局用量由 dsh 原生 UI 显示,此处不重复。
- 排序:非终态(未结算)按 `updatedAt` 升序(卡得最久的最上面);同 updatedAt 按 createdAt。
- 空态:"暂无未结算任务"(选中会话时:"该会话暂无未结算任务")。

5. host 重启:面板保留旧快照,2s 内刷新为最新,无白屏;console 无 error。

## 8. 远期规划:流程 DAG 图可视化与自动排期(本期不实现)

> 记录设计意图,防止 v1.1 的数据契约与后续演进冲突。

### 8.1 目标

- **节点 = 任务**:每个 DAG 节点是一条任务;边 = 依赖关系(前置任务结算后释放下游)。
- **结算联动**:节点任务经历完整流程(settle success)后,DAG 图自动标记为已结算,并释放后方依赖项(下游进入"就绪"状态)。
- **自动排期**:就绪任务的派发由**代码自动执行**(调度器),不依赖人工;PM(发起方)只负责任务拆分与 DAG 制作。
- **DAG 可视化**:面板 v2 增加 DAG 视图(参照 dsh-agent-teams 的 DependencyMap:compactDagLayout 布局 + 悬停高亮依赖链 + 点击固定)。

### 8.2 对 v1.1 的影响(本期规避)

- v1.1 快照不输出已结算任务主列表——DAG 视图需要完整任务集合(含已结算),届时快照增加 `?all=1` 或独立字段,数据契约向后兼容。
- `settled` 字段已定义(3.7),DAG 的"节点已结算"直接复用。
- 面板结构预留:主界面卡片列表与未来 DAG 视图为**同一数据源的两种呈现**,panel-model 的筛选/排序函数与 DAG 布局算法相互独立。

### 8.3 需要的新能力(schema 演进,domain v5)

- `tasks` 表增加 `dependencies: TaskId[]`(指向本工作区内任务;自引用/环由校验拒绝);
- 或独立 `dag` 表(图结构与任务表分离,支持多图);
- 新增工具:`create_dag` / `link_task`(PM 建图),`unblock` 语义并入现有 settle_task(结算成功 → 释放依赖);
- 调度器:宿主端定时扫查就绪节点(所有依赖已结算)→ 自动 dispatch_task(复用现有投递路径,`assignedBy` 仍为 PM 会话,自动派发打标记 `auto: true`);
- 状态机:`submitted` 前增加隐式 `ready`(依赖未清时)或复用 submitted + 依赖字段在工具层拒绝提前派发——二选一,倾向后者(不扩 A2A 词汇表,依赖约束在 ledger 层校验)。
